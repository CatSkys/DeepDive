# Git 提交信息生成（引擎侧插件）

> 状态（2026-09-21）：**已查证可行，未实现**。本文是施工前的规格：语义、接口、落点与验收场景先定死，再写代码（根 AGENTS.md「新增或修改行为前，先更新对应 spec」）。

## 1. 要做什么

提交或推送的对话框里给一枚「生成」按钮：模型读**当前工作树的改动**（可选带当前会话上下文）写一条提交信息填进输入框；留空可点、不满意可再生成（按钮在已有文案时显示为「重新生成」）。

对照：ZCode 的 `GitCommitDialog` 就是这么做的（`packages/ui/src/GitActionMenu.tsx`：生成按钮 `TID_GIT_COMMIT_GENERATE_BUTTON`，handler 在 `handleGenerateCommitMessage`，i18n `git.actionMenu.commitDialog.generate` / `.regenerate`），服务端是 `gitService.generateCommitMessage({workspacePath, locale, includeUnstaged, currentSessionFilePaths?, conversationContext?})` 返回 `{message, providerId, model}`。它**不是**"开框自动填"。

## 2. 为什么本仓现在没有

- 引擎没有 git 能力（`docs/DSH-WIRE.md` 无 git；git 走壳桥 `run-git`/`git-run`，见 `apps/macos/.../AppDelegate.swift`）。
- 引擎也没有通用生成路由：`frontend/src/api.ts` 与 wire 事实源里都没有 `generate*`。
- 所以按钮需要**引擎侧**先有一条方法。

## 3. 落点：随包本地插件

> 这套铺盘（本地文件插件 + `node_modules` 软链 + overlay insert）原先由会话记忆插件
> 实现，该插件 2026-09-24 随「记忆」分区一并移除——本仓现在没有可抄的实现，
> 施工时这一段要照下面三条从零写（`ProfileComposer` 的"失败只记日志不阻塞启动"是
> 唯一还在的同款纪律）。

1. 壳每次启动把插件源码写到 `<DSH_HOME>/deepdive/plugins/git-commit-message/index.js`，并在同目录建 `node_modules` 软链指向随包 runtime 闭包（`Resources/Runtime/dsh/node_modules`）——插件里 `import '@deepseek-ai/dsh-*'` 靠它解析。**闭包不存在时必须删掉旧链接**（否则 boot fail-loud），并回报不可用，由调用方决定不挂。
2. `engine-patch.yml`（`EngineSupervisor.enginePatchBody`）里 `- insert:` 一条挂载；开关与可用性一起决定挂不挂。
3. 引擎组合已归本仓（`engine/profile/cordis.patch.yml`），插件从 dsh 安装闭包解析依赖，不需要改组合。

## 4. 接口

**引擎侧**（插件声明一个 host 面服务，经 `ctx.typert.register` 暴露）：

| 项 | 值 |
|---|---|
| 方法 | `gitCommitMessage/generate`（typert 内部 id 形如 `<包名>#gitCommitMessage/generate`，见 `lib/typert.remote-client.js` 的生成形状） |
| 入参 | `{ workspacePath: string, includeUnstaged: boolean, locale: "zh-CN" \| "en-US", conversationContext?: string }` |
| 出参 | `{ message: string }` |
| 失败 | 无改动 / 模型不可用 → 可读错误；SPA 侧显示在对话框里，不落盘 |

**前端侧**：`frontend/src/api.ts` 增一条调用（dot-form endpoint + client-request 信封）；对话框里一枚图标钮，调用期间禁用并显示 pending。

- 插件能注册引擎 HTTP 路由：`deepseek-harness/packages/api/session-controller/src/media-references.ts`（`ctx.effect(() => ctx.connection.fetch.register({ methods: ['GET','HEAD'] }))`）。
- 插件能声明 host 面服务并被 SPA 调用：`ctx.typert.register({ package, face: 'host', schemas, model, invocations })`（`packages/api/gateway/tests/gateway.host.spec.ts`）；服务侧基类 `TypertRemoteService`（`@deepseek-ai/dsh-typert-protocol`，见 `packages/api/settings-controller/src/index.ts`）。

手写 JS 插件要用 `ctx.typert.register(manifest)` 手工注册（loader 明说这条路留着："Manual

- 官方服务是**声明式**的：类 `extends TypertRemoteService` + 方法标 `@Remote`

**这一步不做完就不动手**——猜这个形状属于铁律 9 禁止的猜测性代码。

## 7. 边界与降级

- 插件**不写会话、不落盘**：只读 diff、只调模型、只返回文本。
- 生成结果由用户确认后才提交；取消对话框不产生任何副作用（与现状一致）。
- 能力缺失（闭包没插件、方法未注册）→ 按钮隐藏，不做假成功；探测沿用 `probeMethod` 的既有口径。

## 8. 验收场景

1. 工作树有改动 → 点生成 → 输入框出现一条与改动相符的信息；再点一次（重新生成）会换一条。
2. 工作树干净 → 按钮可用但提示无改动（或按改动集为空直接禁用），不产生空提交。
3. 模型不可用 / 方法缺失 → 按钮不出现；手动填写的既有路径不受影响。
4. 中英双语：生成的信息语言随 `locale`（词典与设置里的语言一致）。
5. 插件铺盘失败（运行时未嵌入）→ 引擎照常启动、按钮消失（可选能力没有资格把引擎搞死）。
