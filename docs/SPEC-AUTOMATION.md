# SPEC：自动化页面（定时任务）

> 状态：**已实现**（2026-09-12）。拥有「自动化页面」的产品语义与边界；壳桥消息清单归 `frontend/src/host.ts` 头部，引擎 wire 事实归 `docs/DSH-WIRE.md`。

## 0. 一句话

把「重复发起的同类任务」变成可管理的自动化：**到点自动新开一个会话、把指令发进去**，并在一个页面里创建 / 启停 / 立即运行 / 看历史。

## 1. 能力底座与取舍（为什么调度在客户端）

- 引擎在本引脚**没有定时任务 RPC**。`dsh-schedule` 只给模型三个**会话内提醒**工具（`schedule_create` / `schedule_list` / `schedule_delete`，到点向**原会话**追加一条消息），不能新建会话；也没有「列出/创建定时任务」的远端面。所以「到点新开会话跑一条指令」只能由客户端驱动。
- 取舍：任务清单与调度住在**客户端**（`localStorage`，`automation/storage.ts`；跨重启保留的前提是网页 origin 稳定——桥端口固定，见 PITFALLS §4.17），代价是**应用没运行时不会触发**——这是明示语义而非留白（§4）。为把代价压小：启动补差窗口 5 分钟（错过更久的直接顺延，不让开机补跑一串）；「运行会话时保持电脑唤醒」让到点前 Mac 不因空闲休眠睡过去。

## 2. 形态

- **入口**：设置页左侧导航的**自动化**分区（用户定稿：不进侧栏）。列表与编辑器都装在这一个分区里，「历史」里点「打开会话」会关掉设置页去看那次转录。
- **列表页**：说明 + 创建入口 + 保持唤醒开关 +「已创建任务」卡片 +「定时任务模板」四张（点模板只把示例填进新建表单，不直接建任务）。
- **编辑器**：新建与编辑同一张表单（任务标题 / 调度 / 指令 + 运行选项：工作空间、权限预设、模型、思考档位），配「设置 / 历史」两页签。右侧动作按态不同：新建给「创建定时任务」，编辑给「保存 / 立即运行 / ⋯（继续·暂停、删除）」；字段写入统一经「保存」提交，状态胶囊改的是草稿，⋯ 菜单里的继续/暂停与删除立即生效。
- **计划类型**：每小时 / 每天 / 每工作日 / 每周 / 每月 / 自定义（每 N 天，于 HH:MM）。按**本机时区**生效，编辑器显示 GMT 偏移（不可改）。次回触发时刻是纯函数 `nextRunAt`（按日历推进，跨月/夏令时不漂）。
- **运行**：`api.createSession({workspaceId})` → `selectModel` → `/permission <预设>`（引擎唯一的按会话权限写入口）→ `prompt(mode:'queue')`。卡片「立即运行」跑完跳去那次会话；到点触发不打断当前视图，只在卡片上显示「运行中…」。
- **运行目标（任务级选项，表单底部）**：`每次新建会话`（默认，一次运行 = 一条独立会话，上下文干净）／`复用同一会话`（首次运行创建并把 sessionId 记进任务，此后每次往同一个会话里发，上下文累积）。复用的前提是那个会话仍在引擎列表里——被删了就下次运行重建一个并记回（不静默失败也不卡住）。
- **历史**：每次运行一条记录（时间 / 进行中·已完成·失败+原因 / 打开会话），每任务保留近 50 条。引擎没有「会话结束」事件，收尾靠轮询到的 `SessionSummary.running` 对账（10 秒宽限，引擎离线时不改写状态）。

## 3. 会话里创建自动化（协议）

会话里也能建任务：模型按固定格式给建议，用户在应用里过一眼再创建。

- **协议**（`frontend/src/automation/protocol.ts`）：回复里输出 info string 为 `automation` 的围栏代码块，内容是一个 JSON 对象——`title`、`instruction`、`schedule`（本项目的六种计划形状之一）、可选 `workspace`（工作空间**标题**）与 `permission`（预设键）。
- **消息流**：SPA 认出这个围栏块就渲染成一张「定时任务建议」卡（标题 / 计划 / 指令摘要 + 创建按钮）；**解析不了就退回普通代码块**——模型没按格式写不冒充建议，也不报错。
- **点创建**：派发应用内事件，App 打开设置→自动化的新建表单并预填；工作空间按标题匹配，匹配不到就用当前空间（表单一目了然，用户自己决定要不要改）。**落库仍由用户点「创建定时任务」**，不静默创建。
- **教模型（skill，不是常驻提示词）**：协议正文住在引擎的 **skill** 里——壳每次启动把它写到引擎的用户技能根 `<DSH_HOME>/skills/deepdive-automation/SKILL.md`（`EngineSupervisor.ensureAutomationSkill`，默认发现路径，不需要改装配），模型在用户提到定时任务时经 `skill` 工具按需加载。`engine-patch.yml` 的 `system-prompt` 前缀只剩**一行指路**（"要建定时任务就加载 deepdive-automation skill"），不再把整份形状挂在每个会话的上下文里。三处是**同一份契约**：`protocol.ts`、skill 正文、那行指路，改一处必须同步其余（注释都写了）。
  - skill 文件的 frontmatter 是硬契约：缺 `name`/`description`、或用了 legacy 键（`modelInvocable` / `userInvocable` / `disableModelInvocation`）会**抛错**，引擎只记一条 warn 然后**静默忽略整个 skill**——模型就再也看不到它。壳的单测钉住了这两个坑与六种计划形状。
- **与引擎自带提醒的分工**：一次性/会话内的提醒仍走引擎的 `schedule_*` 工具（到点往**原会话**追加消息，展示在会话头部的状态胶囊里，只有模型能改）；「按计划、每次开新会话跑一轮」这类才用本协议建任务。两者不互相替代，提示词里也点明了别混用。

## 4. 与参考实现的刻意偏差

- **闲时任务页签**：用户明示不做。
- **刷新按钮**：任务清单是本机数据，没有可重取的远端，摆了就是死控件。
- **「去会话中创建」**：引擎没有能让模型写进本机任务清单的工具，点了只会开一个空会话——不如不给。

## 5. 非目标

- 不做跨设备同步；不做引擎外常驻调度器；不引入新引擎插件。
- 不做「应用关闭也照跑」（那需要常驻代理或 launchd，属另一件工程）。

## 6. 验收口径

- 创建 / 编辑 / 启停 / 删除即时生效且跨重启保留（`localStorage`）。
- 到点或点「立即运行」在目标工作空间产生一个会话，转录与手发一致（同一 `prompt` 面）。
- 历史里每次运行可回溯到那次会话；失败带原因。「复用同一会话」的任务，多次运行的记录指向同一个会话。
- 会话里按协议提出的建议能在消息流里点开、预填并在表单里创建；不按格式写的内容仍按普通代码块显示。
- 保持唤醒开关打开且**有会话在跑**时系统空闲休眠被按住（`pmset -g assertions` 可见 `PreventUserIdleSystemSleep named: "DeepDive: session running (keep awake enabled)"`），停跑即释放。
