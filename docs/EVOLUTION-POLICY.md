# EVOLUTION-POLICY — 自进化提案政策（可演进）

> **本文件是「什么值得沉淀、能写到哪里、怎么算有效」的唯一事实源**，也是二级进化的对象：改这份文件同样走"提议 → 人审 → 落库"，改动对象就是它自己。
> 设计语义与出处见 `docs/SPEC-SELF-EVOLUTION.md`；各知识家的写作规范归它们自己的文档（`AGENTS.md` 的维护条款、`docs/PITFALLS.md` 的条目格式）。
> 协议与触发判据（怎么输出、什么时候提）归引擎技能 `deepdive-evolution`，本文件只写"标准与红线"。

## 1. 允许清单（能写到哪里）

| home | 目标文件 | 什么样的经验进这里 |
|---|---|---|
| `agents` | `AGENTS.md` 的规则区 | 跨会话常驻的**行为规则**（1-3 行 + 链接到它的家） |
| `pitfalls` | `docs/PITFALLS.md` | 真实事故：症状 + 根因 + 处置 + **诊断锚点** |
| `spec` | `docs/SPEC-*.md` 的设计段 | 产品 / 协议语义边界的确定 |
| `skill` | 引擎技能正文 `SKILL.md` | 可复用的操作流程（黄金路径，含走过的死路） |
| `policy` | 本文件 | 提案策略本身（判据 / 阈值 / 清单） |

代码、脚本、配置、构建产物**一律不在允许清单内**（依据见 SPEC §5：四个参考项目没有任何一个把产品代码当进化对象）。

## 2. 类别与判据（什么算值得提）

- `incident` **事故**：真实踩过、有可复现症状的坑。同一坑出现第二次 → 必提。
- `workflow` **流程**：试错数轮才走通的路径。**连死路一起记**——"下次别再试 Y"常常比成功本身值钱。
- `fact` **事实**：非显然的项目事实（凭据在哪、怎么验证线上、这条流水线的隐藏前置）。
- `rule` **规则**：应当常驻的行为约束（进 `AGENTS.md`）。

**不值得提**：一次性任务的细节、实现结果、助手的自我总结、"用户没有再提到"这类推断。

## 3. 证据门槛

- 每条提案 **≥1 条逐字证据**：`sessionId` + `turn` + `eventSeq` + `excerpt`（≤500 字，**逐字**摘录）。
- **助手内容只能作上下文，不能单独充当证据**；一次性任务细节不作证据（照 `dsh-evolve-modes` 的证据条款）。
- 证据从会话日志取：`<DSH_HOME>/sessions/<bucket>/<sessionId>/session.v3.jsonl.zstd`（`zstd -dc … | grep …` 即可核）。

## 4. 效果主张（提案必须可被证伪）

- `metric: repeat-incident` —— 给出**可 grep 的签名**（提出前必须先在日志里自证能命中一次）+ 观察窗（默认 14 天）；目标：窗口内复现 **0 次**。
- `metric: steps` —— 给出同类流程的匹配签名 + 落地前的工具调用数基线；目标：至少 **−30%**。
- 给不出可量主张的标 `style: true`：可以沉淀，但**不进效果统计**（防止拿"感觉更好用"凑数）。

形态取自 penguin-harness 的「rubric 打分 → 再评估 → 均分提升才保留」；把 rubric 换成"日志上的复现次数 / 步数"是**本地适配**（我们没有基准任务集，这一点不装成别人的做法，详见 SPEC §6）。

## 5. 运行参数（默认值，可改）

| 参数 | 默认 | 说明 |
|---|---|---|
| 学习批次 | 攒够 3 轮 + 距上次 ≥24h | 触发一次后台复盘。参考（dsh-evolve-modes）是"每 3 次回复一次廉价学习调用"，我们这一轮是完整 agent（要挖日志），所以加了日节流 |
| 待审上限 | 100 | 到顶不再堆积 |
| 校验窗口 | 14 天 | 到期校验的观察窗 |
| 模式 | `Propose` | **只提议，永不自动改变行为**；落库必须过人 |
| 总开关 | 默认**关** | 实验性能力 opt-in（设置→自进化）：关着不采集、不复盘、不校验，装配层也不写那行指路 |
