# DSHmini 协作约定（用户定稿，长期有效）

> 用户明确要求的工作准则。每次会话/每轮改动必须遵守。

## 1. 先看代码，不质疑用户

- 用户报告任何"没生效/不对"的截图或描述时，**第一步是读源码与构建产物**（`git status` → 读相关文件 → `grep` dist 产物验证），**绝不用"旧实例/没重启"之类的说法打发用户**（2026-09 教训：用户端截图与本地差异、样式"动都没动"的真因是后置重复 CSS 定义覆盖新规则——源码里就能发现，不必怀疑用户环境）。
- 结论必须以**代码/产物实证**给出（如：`grep -c` 结果、规则顺序、dist 中的实际值）。

## 2. 验证与验收的分工

- **验收归用户**：功能对不对、界面好不好看，由用户在真机里看。agent 交付到"应用已重启、可以直接看"这一步即可，**不自行截图、不自行做视觉验收**（用户 2026-09-27 定："以后测试验收通通由我来，你只需要重建重启打开，也不要截图了"）。理由：验收是用户的判断，agent 越俎代庖越慢，且抢占用户正在用的鼠标键盘。
- agent 该做的仍是**代码层自证**：改样式/布局类问题必须用可量化的方式确认（`getBoundingClientRect` 量坐标、读 computed style、`grep` 构建产物），把数字摆出来——"箭头右缘 1162 与工具行一致"比"看起来对齐了"可信。这是代码验证，不是替用户验收。
- **取数口 `scripts/probe.py`**（壳侧 `UiProbe` 提供数据）：量运行中窗口的矩形、computed style 与原生层几何，省掉"临时 evaluateJavaScript 再还原"那一套。用法见脚本头部；它只回数据，不产出视觉判断。
- **只在用户明确要求时**才做端到端测试/截图/多轮探针（"你让我测试你再测试"）。默认不做。
- **验证顺序（被要求做时）：浏览器优先，桌面控制最后**（用户 2026-09-04 明确要求）。前端 UI 的调试与回归先用浏览器做：bridge URL + browser-use/Playwright（见 PITFALLS §6.2），可精确到 DOM/样式且完全不碰用户的鼠标键盘；`computer-use` 桌面控制只作最终真机验收、动作尽量少——它会抢占用户正在进行的光标与键盘操作。
- 打包重签会让 TCC 文稿授权重置，启动弹"想访问文稿"系统框并模态挡住应用初始化（PITFALLS §4.8）：点允许即可，不是回归。
- **偏好/桥指令类 UI（开关、持久化）的验收必须在真机 WKWebView 里做**：纯浏览器页（IAB/Playwright）没有壳桥，`sendToShell` 按设计静默无效——开关会"看着生效、刷新即丢"，那不是 bug 而是上下文缺失（2026-09-04 教训：在 IAB 里反复点快捷键开关误判为不持久化）。

## 3. 只修用户指出的问题

- **不扩大修复范围**：用户没提的（如光斑、材质、背景）不主动改，更不借题发挥做"顺手根除"（2026-09 教训：用户明确"我没提光斑啊…你 tm 别修了"）。
- 连续两次被同一处驳回时，先停手，回读需求与代码，再动手。

## 4. 交付纪律

- 交付命令链固定：`前端 build → Release 构建+嵌入 → pkill 旧进程 → open 最新包 → 日志确认`，已固化为 **`make deliver`**（scripts/deliver.sh）；分发档（公证+装钉+DMG）仍走 `make package`。
- 文档/规范同步更新（REVIEW、本文件），改动即提交。
- 单实例：临时验证代码（TEMP 标记）必须当轮还原，避免把调试态交付给用户。

## 5. 并行会话与 worktree 纪律（用户 2026-10-12 定稿：必须，无关大小）

- **主仓一律只收合并，不接受任何直接改动与提交——无关大小，一行修复也要开树**：任务用 `scripts/new-worktree.sh <slug>` 开 `DSHmini-<slug>` 树（分支 `feat/<slug>`），merge 一律 `--no-ff`（一个任务一个合并提交），收尾 `scripts/remove-worktree.sh <slug>` 删树删分支，不留残树。
- **机械卡点**：pre-commit 钩子（`scripts/git-hooks/`，`make hooks` 启用 `core.hooksPath`，worktree 与主仓共享该配置）在主仓检出上拒绝 commit；merge 不经过钩子。确需例外 `git commit --no-verify`（绕过是显式动作，不是默认）。
- **每个任务的完整流程**：开树 → 树内改 + 验证（简单改动 `make check`；行为改动 `make test`，测试支撑目录按树隔离于 `.build/test-support`，多树可并行测试）→ 回主仓 `merge --no-ff` → 主仓 `make deliver` 交付 → `scripts/remove-worktree.sh` 清场。
- **多个 agent 会话不共用同一个 working tree**（2026-10-11 教训：并行会话把彼此进行中的 WIP 卷进自己的 feature 提交，历史归属错乱；中断会话遗留的测试宿主占锁，后续 XCTest 全体秒挂）。
- **棘轮基线与词典不并行改**（architecture-baseline.json、i18n-en.ts 等）：merge 必撞；动基线的任务独占进行。
- **提交前 `git status` 复核**：只暂存本任务文件；非本任务 WIP（其他会话/用户的）拿不准就不 add。
