## 0. 外观、原则与不变式

> 本节三块、外加下面两份清单，分工不重叠：**不变式**＝"改了就悄悄坏掉"的编辑约束；**§4 验收清单**＝发布前逐条过的 gate；**§6 拒绝清单**＝明确不做的东西。同一件事只在一处写死，别处引用。

### 外观（一段话）

主窗是一整块近黑玻璃：界面画在透明的 `WKWebView` 里，材质由窗口底板从桌面透上来（macOS 26+ 用 Liquid Glass，更早的系统退回 `NSVisualEffectView`＋近黑 tint，见 §1.5），窗口自己不透明就退化成窗内混合的平灰。面板与侧栏用半透表面透出这层材质，正文所在的卡取近实色——底下是用户壁纸时正文才读得清。主题只有黑白灰阶、没有强调色，状态靠**符号 + 亮度**表达而不是靠颜色；大圆角；**有底色的卡片一律不描边**，范围靠底色区分。会话列与右侧面板是**两张并列的悬浮卡**，四周与两卡之间各留 8px 缝，缝里透出背景层。内容超出容器时不画裁切线、不露裸滚动条，用两侧渐隐表达"后面还有"（FadeEdge；会话流顶端另叠一层渐进模糊的雾带）。悬浮控件（菜单、命令面板、胶囊、浮窗）走真半透 + `backdrop-filter`，对话框用更实的近实色底。文案只承担一种职责——标题、动作、占位或分组标签——没有副标题与解释性小字。

### 设计原则

1. **快（Fast）**——主流程 ≤2 次按键；快捷键永远可见（操作栏右侧键帽）；面板即焦点即输入。
2. **简单（Simple）**——一屏一个重点（输入框 / 会话流）；无装饰性内容；状态一眼可读。
3. **愉悦（Delightful）**——动效只出现在"发生"的地方。
4. **原生感 = 行为为先**：**光标不给控件**——手形只给正文里的超链接；**hover 不表达状态**——行与菜单项的高亮只由"指针主动移过来"触发，绝不因为指针恰好停在那里就亮（机制见 §1.10）；设置独立窗口；弹层原生可越界；面板 vibrancy 透出材质；无白帧。
5. **一致（Consistency）**——一套 token（`tokens.json` → `tokens.css`）、一个样式事实源（`theme.css` 的语义变量 + 各 `*.module.css`）；同类控件复用同一份类名配方，不写第二套。
6. **黑白（Monochrome）**——主题色只有黑与白（表面对应灰阶、亮度差）；**无强调色**。状态表达靠**符号 + 亮度**，不靠颜色：
   - 等待你 → 白点 ⚠ + 行整行亮度选中 + 呼吸；失败 → ✕ + 行高亮；完成 → ✓（灰）。
   - 彩色仅允许一处：**diff 增删**的绿红（内容层语义色，非主题色；如评审不同意可去除，改为 +/− 符号）。
7. **少字（Anti-Copy）**——文案规则见 §1.9：一切解释性小字、副标题、状态说明＝冗余。一行话能表达的，绝不用两句；一个词能表达的，绝不用一句。

### 不变式（不可协商）

以下是"改了会悄悄坏掉"的东西——**不报错、不红测试，只是样子变差**。除非任务明确就是改它，否则不要碰；括号里是它的家。

- **暗色是基准，亮色是反色推导。** 一个表面色先定暗色档，亮色跟着推；任务不是改暗色就别动暗色档。两列语义与"明暗间刻意不变的三类"见 §1.1。
- **单一入口。** 颜色/间距/圆角/字号只经语义变量（`--ink`/`--line`/`--fill` 一族）与 token 取用，禁止就地写色值、灰色（`#888`/`gray`）或手写数值（§1、§5）。
- **表面材质只有两族**，且两族的差只在**回退底色**（菜单族真半透 `.55`／对话框族近实色 `.92，`.92` 承载正文）与回退模糊档：拿到系统材质时那一层**没有底色也没有 CSS 模糊**，整块面由材质自己画（§2.2bis 硬约束 2）。新浮层加入对应族即得，别自造第三套。
- **玻璃只给悬浮控件。** 主表面永不玻璃（它是"scrim + 背后模糊"）；对话框是刻意的模态例外（§1.5）。
- **卡片与行的语法是全站共享的。** 有底色不描边、分组行分隔线两端缩进（禁全宽横线）、区块标题与内容间距 ≥12px——**改一处就要全列表一起改，分叉是 bug、不是 feature**（细节与例外见 §2.4）。
- **状态靠符号 + 亮度，不靠颜色。** 彩色只能出现在已登记的内容层例外里（`diff` 增删、`chart` 编码色、`signal` 组），新增一处必须登记（§1.1）。
- **少字。** 无副标题、无解释性小字、无行内 meta、无状态说明注脚；例外逐条登记在 §1.9 末条，新增例外同样必须登记。
- **渐隐替代裁切。** 内容超限只许用 FadeEdge / 会话流雾带表达"后面还有"，禁生硬裁切线与裸滚动条（§2.1）。
- **窗口底板必须 `isOpaque = false` + 背景透明**，否则玻璃退化成窗内混合的平灰，且不会报任何错（`PITFALLS §4.27`）。
- **动效只引词汇表**（`--dur-*` / `--ease-*`），不写字面量；场景对应关系见 §1.7。
- **光标只给正文里的超链接；行与菜单的 hover 只由指针移动触发。** 样式侧的那道门是 `:where(html[data-hover-armed])`，机制侧是 `hoverArming.ts`（§1.10）。**删掉这道门就等于回到"指针停在哪儿就亮哪儿"**——它在滚动、流式重排、浮层在静止指针下打开这几种情况下都会骗人，而且页面照样能跑、测试照样全绿。
- **禁区：会话流的六层渐进模糊与它的一族常数**（`.session-fade`、`--session-fade-*`、`--flow-fade-live`），以及 `FadeEdge` 的 mask 参数。它们是对着浮动条与滚动深度**用眼睛调出来**的，任何编辑都是视觉回归。**想改它来修滚动 bug，意味着真正的修复在别处**——"改前必读"的四条与算法说明在 `theme.css` 的 `.session-fade` 注释里，两层 mask 的用途见 §2.1。

## 1. 基础设计 Token（初值，评审后可调）

### 1.1 颜色（明/暗两套；主题 = 黑白灰阶）

> **实现**分两处：**文字与内容层彩色在 `tokens.json`**（`color.ink` / `signal` / `diff` / `chart` 与
> 顶层的 `contrast`），**表面/描边/终端/遮罩/焦点环在 `theme.css` 的语义变量**
> （`--line`/`--fill`/`--panel-*`/`--terminal-bg` …）。**要改值改实现那一处**，本节的表是实现的上游意图。

#### 文字色阶 = 一个基色 + 统一 alpha 停靠点（`color.ink`，Raycast 口径）

色阶不是六组手写值，而是 `color.ink.base`（light `#000000` / dark `#FFFFFF`）按
`color.ink.stop`（100 / 80 / 60 / 40 / 20 / 10）展开。**生成器在生成期解析成具体 rgba**，
CSS 侧只剩别名——两套主题共用同一份停靠点，**换主题只改基色一个数**。

| 变量 | 停靠点 | 对应 Raycast | 用途 | 压卡面对比度（暗 / 亮） |
|---|---|---|---|---|
| `--ink` | 100 | primary | 正文、标题、数值、链接 | 21.0 / 21.0 |
| `--ink-soft` | 80 | token-secondary | 压过正文一档的强调 | 13.1 / 12.6 |
| `--ink-2` | 60 | secondary | 次级：分组标签、元信息、占位 | 7.4 / 5.7 |
| `--ink-3` | 40 | tertiary | 三级：时间戳、弱说明 | 3.7 / 2.9 |
| `--ink-faint` | 20 | quaternary | 四级：极弱点缀 | 1.7 / 1.6 |
| `--ink-faintest` | 10 | — | 五级：仅作痕迹 | 1.2 / 1.3 |
| `--on-ink` | 反色基 80 | — | 反色面上的前景（实底按钮的字、开关旋钮、选中标签） | — |

**正文占满最高档，没有"比正文更亮"的一档**——所以"hover / 选中把字提亮"这种暗示在本仓不成立，
可点与悬停一律走**填充**（`--row-hover` / `--fill`，§1.10）或**下划线**（文字可点）。
承载正文的面（`--card-gradient` / `--panel-*`）基色同样取纯极值（纯黑 / 白叠加），
与基色同为极值——上表的对比度才是真实值。

#### 表面与描边（`theme.css` 承担）

| 语义变量 | 亮 | 暗 | 用途 |
|---|---|---|---|
| `--panel-strong` | `rgba(255,255,255,.94)` | `rgba(0,0,0,.92)` | 弹层 / 对话框 |
| `--panel-glass` | `rgba(255,255,255,.55)` | `rgba(0,0,0,.55)` | 菜单浮层的明显毛玻璃档 |
| `--panel-palette` | `rgba(255,255,255,.90)` | `rgba(42,42,42,.82)` | 命令面板（比铬件抬高一级亮度） |
| `--card-gradient` | 白 `.96/.97` | 纯黑 `.96/.97` | 内容卡（近实色，正文的底） |
| `--fill` / `--fill-strong` / `--fill-heavy` | 黑 `.055` / `.09` / `.15` | 白 `.07` / `.11` / `.20` | 填充三档 |
| `--row-hover` / `--selection` | 黑 `.045` / `.16` | 白 `.05` / `.20` | 行 hover / 选中 |
| `--line` / `--line-strong` / `--line-heavy` | 黑 `.12` / `.20` / `.36` | 白 `.10` / `.17` / `.30` | 描边三档 |
| `surface.inverted` | `#FFFFFF` | `#2A2A2E` | 反色强调（标题底下衬、激活项） |
| `border.default` / `border.strong` | 黑 `.11` / `.22` | 白 `.09` / `.18` | 分隔线、输入框/浮层描边 |
| `--line-focus` | 黑 `.62` | 白 `.85` | 键盘焦点环（黑白主题） |
| `--terminal-bg` | `#F2F2F4` | `#1A1A1D` | 代码块/终端输出底色（恒深色内容面） |
| `--veil` / `--overlay-scrim` | — | — | 模态与预览蒙版 |

**两列的主从：暗色是基准，亮色是反色推导。** 一个表面色先定暗色档，亮色是同一套语义的反色结果；改亮色随意，动暗色档要有一个"这个任务就是来改暗色"的理由。两列都经语义变量落地（§0 不变式的单一入口）。

**明暗间刻意不变的三类**（反色会让它们失效或失真，改前先读这一条）：

1. **内容层语义色恒为色相**：`diff.add/del` 的绿红、`chart.*` 的系列色与热力格五档——明暗各有一组值，但永远是那个色相，不参与黑白化。
2. **`signal.*`（warn / live / danger）明暗同值**：它们是收编进来的内容层例外，不随主题反色。**同值不等于直接可用**——把暗色调的彩度原样搬到白底上会大面积不可读（`signal.live` 压亮面 1.54:1、`diff` 绿压自己的染色底 1.43:1），所以这三个色与 diff 的两个 ink 都必须经下面的校正层取用。
3. **渐隐类 mask 是遮罩亮度，不是颜色**：FadeEdge 与会话流雾带一旦反色，渐隐在所有列表上一起失效。

#### 彩字的对比度校正层（`tokens.json` 的 `contrast`，照 Raycast 的 `--x-contrast` / `--x-on-tint`）

内容层彩字有**两种落点**，同一份色值两处都用必有一处不可读：

| 变体 | 落点 | 消费处 |
|---|---|---|
| `--dsh-<色>-contrast` | 直接压卡面 | `--dsh-signal-*-contrast` 的所有 `color:` 用法；`--diff-*-ink-on-card` |
| `--dsh-<色>-on-tint` | 压自己的染色底 | `--diff-*-ink`（`.diff-line` / `.rv-line` 是"染色底 + 同色系字"） |

生成器按 `contrast.on`（纯极值面）与 `contrast.target`（4.5）给每个色算出**达到门槛的最小改动**：
达标就不动，不达标才朝离背景更远的一端插值，并对 8 位取整后的结果复验（取整会吃掉 0.02 左右）。
Raycast 用 colorjs 在运行时做这件事（它的主题是运行时可换的数据）；我们主题是静态两套，
所以放在生成期——不引运行时依赖，产物仍是可审阅的静态值。**这两族是唯一合法的取用方式：
不要再直接 `color: var(--dsh-signal-x)`。**

- 对比度验收：正文 ≥ 4.5:1，次级 ≥ 3:1；**彩字两种落点同样按 4.5 卡**（校正层保证，改完跑生成器复算）。
- 色彩纪律：**主题铬只允许黑白灰阶**；彩色只出现在已登记的内容层例外里（`diff` 增删、`chart` 编码色、`signal` 组，全部收编在 `tokens.json`），任何其他颜色（含青/蓝/紫）＝评审拒绝；状态一律符号 + 亮度，不引入彩色。**新开一处彩色必须在 §1.1 登记，并说清它为什么是"内容"而不是"铬"。**

### 1.2 字体

**本节是字体的规范：下面每一条都是"决定"，不是现状描述。** 口径对齐 Raycast（它桌面端的 UI 就是
一套 Web 前端产物，规范可从其 bundle 的 CSS 与主题数据直读），与它不一致的地方都写明了理由——
包括我们**故意不跟**的几处。改字体相关的任何行为，先改这一节。

| Token | 值 | 用途 |
|---|---|---|
| `font.ui` | `"Inter Variable"`（**随包内置**，OFL）＋ 系统栈兜底（`-apple-system` → `Segoe UI Variable Text` → `PingFang SC` → 微软雅黑） | 全系统一：拉丁由内置字体出字形，**中文仍落系统字体** |
| `font.mono` | `"JetBrains Mono Variable"`（**随包内置**，OFL）＋ `"SF Mono"` → `"Cascadia Mono"` → `ui-monospace` → `Menlo` | 代码、diff、上下文卡小标题、计数 |
| `font.base` | 13px | 阶梯基准（`--dsh-ui-font-size`）：只改它，整梯一起动 |
| `font.size.xs` | base − 3 = 10px | 键帽、徽标、计数、极弱元数据 |
| `font.size.sm` | base − 2 = 11px | 次要文案、分组标签（Pinned / Recent / Last Week）、浮层小标题、Tooltip、行内代码 |
| `font.size.base` | base = 13px | **正文默认**：正文、按钮、列表行、会话标题、markdown h3、代码块正文 |
| `font.size.lg` | base + 3 = 16px | 分区/弹窗标题、markdown h2 |
| `font.size.xl` | base + 5 = 18px | markdown h1、浮层大字形（灯箱关闭/缩放）、⌘K 面板的查询行 |
| `font.size.hero` | 24px（**显示级**，不随基准） | 面板主标题、引导页标题、页内一级标题、环图中心数 |
| `font.weight` | 400 · 500 · 600 仅三档 | **600 = 标题（lg 及以上档）与数字/表头；500 = 其余一切强调**（列表行名、分组标签、选中态、按钮、字形）；400 = 正文与**键帽**（键帽是正文，不是强调：参考面板的 `.shortcut__kbd` 从不设字重，继承根元素的 400） |
| `num.style` | `tabular-nums` | 计数、耗时 |

- 六档一律由基准加偏移生成（`calc(var(--dsh-ui-font-size) ± Npx)`），**禁止**在规则里手写字号：写 `var(--dsh-font-size-*)`——架构门规则 9 会拦手写 px。偏移表**不等距**（−3/−2/0/+3/+5，照 Raycast 的 8/11/13/16/18/24 收敛；最低档取 10 而不是 8：xs 承载中文微文案，8px 汉字不可读，而 10px 恰是 Raycast 自己键帽组件的档位）。迁移口径同 ZCode——遗留的 12.5/13px 归 `base`（不是新建一档），11.5/11px 归 `sm`，10px 归 `xs`。
- 字重与字号是**两个独立决定**（`font-weight` 逐规则写，不焊进字号档）；行高同理。
- **字重只有三档、600 是上限**：600 只给「有字号档提升的标题（lg 及以上）」与 markdown h1–h3、数字/表头；其余强调一律 500——界面的层级靠位置与字号表达，字重只需比正文重一档（这是 Raycast 语义变体层的口径：`text-strong` 全档 500，600 只出现在 heading 与 mono-strong）。**700 在中文上不是加粗而是合成加粗**：PingFang SC 的真实字面最高只到 Semibold，700 只能由 WebKit 描边伪造（笔画发糊发闷，中文界面显廉价的典型来源）。700 收回过两次（2026-09-30 全仓 13 处、2026-10-14 又收 3 处），架构门规则 9 现已机械拦 `700/800/900/bold`。
- **字距随字号反向**（Raycast 口径：30–40px 用 `−.01`~`−.025em`，8–16px 用 `+.005`~`+.06em`）。三档取法：
  · **正文与 UI（base 13 到 lg 16）不设字距**，用字体自带度量；· **小字标签**（≤ `sm` 11：分组标签、表头、全大写）放宽 `+.02em`~`+.03em`——弱色小字不放开会显得散；· **显示级大字**（`xl` 18 及以上、`hero` 24）收紧 `-.01em`——大字沿用正文字距会松散，这是最容易走反的一档。等宽不设字距。唯一例外是 §1.8 键帽里的组合键符号（`letter-spacing: 2px`，让 ⌘ ⇧ 之间留出正常文字间隔）。2026-10-14 对齐时发现 `hero`/`xl` 写的是 `+.01em`，方向与本条相反，已收回。
- **不启用任何 OpenType 风格集（`ss01`–`ss20`）**：`kern` / `liga` / `calt` 在浏览器里本就是默认开启，我们依赖默认，因而不写 `font-feature-settings`（写了也是空转）。Raycast 额外开了 `ss03`——**我们没开，因为没法在本地证实它改的是哪几个字形**（铁律 9：不猜）。要开必须先验证效果并在本条登记。
- **字体合成只关字重**（`font-synthesis: weight`）：`700` 在中文上是合成加粗（PingFang SC 最重只到 Semibold，PITFALLS §1.21），关掉它，中文在 raw `<b>` / `<strong>` 这类不受 §1.2 字重口径管辖的地方会回落到真实的 Semibold，而不是被 WebKit 描边伪粗。**不关字形合成**——Raycast 用一句 `font-synthesis: none` 把两者一起关，是因为它随包带了 Inter 的斜体面；我们只引正体（`index.css`），一起关会让那 2 处 `font-style: italic` 失去斜意，而合成斜体在拉丁上是无害的。这是与 Raycast 的第一处**故意不一致**。
- **不设 `font-optical-sizing`**：我们引的是 `wght` **单轴**变体（`@fontsource-variable/inter` 的 `index.css` 指向 `*-wght-normal.woff2`），字体里根本没有 `opsz` 轴。Raycast 的 `font-optical-sizing: none` 照抄过来是一条空属性，只会让人以为调过什么（同 §1.21 那类"静默"）。
- **抗锯齿取 `antialiased`（灰度）**，与 Raycast 的 `subpixel-antialiased` 不同：本仓是深色玻璃界面，子像素抗锯齿的彩边在深底上更明显、字也发糊。这是第二处**故意不一致**；要换是一行的事，换之前先在真机比。
- **行高逐规则决定，不设 token**（与字号、字重三者互相独立）。取值收在这几档：单行控件用与盒高对齐的固定 px（或 `var(--flow-row)` 这类既有变量）；多行正文用 `1.5` / `1.6` / `1.65`；标题用 `1.2`~`1.3`；显示级大字用 `1`。
- **数字用 `tabular-nums`**（`num.style`）：只给需要上下对齐的数字列——计数、耗时、表头、统计值；正文行内的数字不加（等宽数字在行内会显得稀疏）。
- **字体资产随包内置**（tokens v15）：拉丁用 `@fontsource-variable/inter` 与 `@fontsource-variable/jetbrains-mono`（OFL，无运行时下载；dist 增量约 312KB），系统字体只作兜底。**族名必须按各自 `@font-face` 的声明原样写**（`Inter Variable` / `JetBrains Mono Variable`，不是包名 `Inter`）——写错是静默的：整族回落系统字体，页面看着"还行"但字重与字距全变（PITFALLS §1.21）。只打包拉丁子集，所以中文仍由 PingFang／微软雅黑出字形，⌘ ⇧ 这类内置字体没有的符号逐字回落系统字体（§1.8 键帽因此仍钉 UI 字体栈）。
- 例外：图表轴标签（`UsageTrend` 的日期轴）、mermaid 主题字号、KaTeX 的 `1.02em`、首字母 monogram 的几何推导字号**不进阶梯**——它们是图表/图形内部件，随容器几何走（这几处正是 TSX 内联 `fontSize` 的全部消费者；规则 9 只查 CSS）。
- **壳侧不在本表**：AppKit/SwiftUI 有自己的字号（13/12/11）与字重（Regular/Medium/Semibold），不经 `tokens.json`（架构门的判据就是"Swift 壳的样式不归 tokens.json 管"），且 woff2 无法给 AppKit 用，所以壳侧继续走系统字体——两套并存、层级不重叠（Raycast 同样的分法）。
- 跟随系统字号缩放（P2，未做）；中文不斜体。
- **机械卡点**：架构门规则 9 拦「手写 px 字号」（必须走 `var(--dsh-font-size-*)`）与「700 及以上字重」；本节其余各条（字距、OpenType 特性、字体合成、抗锯齿、行高取值）靠评审——改动前先读本节，改了行为就回来改这一节。

### 1.4 圆角 / 边框 / 高光 / 阴影

**阶梯八档**（`tokens.json` 的 radius 组是唯一事实源；档间没有第二套值——网页侧手写圆角为零，`make test` 的架构门会拦）。**壳侧的同一套刻度在 `Support/ShellDesign.swift`**（`ShellRadius` 镜像本表，改一处必须同时对另一处改），窗口层级表（`ShellWindowLevel`）与原生独有的动效值（`Support/ShellMotion.swift`）同在 `Support/`：

| Token | 值 | 用途 |
|---|---|---|
| `radius.micro` | 4px | 12–18px 微元素的几何：勾选标记、图标底板、热力图格、量表条 |
| `radius.keycap` | 6px | 键帽、迷你图标钮、小标签 |
| `radius.row` | 8px | 命令面板族的行：⌘K 面板、命令中心卡的历史/设置/选择行（= 参考面板拟合出来的 r ≈ 7.5–8） |
| `radius.control` | 10px | 按钮、输入控件、其余行、设置行 |
| `radius.card` | 14px | 卡片与紧凑浮层：工具卡、diff 卡、对话框、右键菜单 |
| `radius.panel` | 18px | 面板与主卡（= window 26 − 8 缝，HIG 同心规则） |
| `radius.floating` | 20px | 大型浮层：模型菜单、命令面板、浮动会话卡、迷你命令中心 |
| `radius.bubble` | 24px | 聊天气泡软胶囊；**胶囊一律写它** |
| `border.width` | 1px `border.default` | 通用描边 |

**两条语义形状，不是阶梯档**：圆 `50%`（等宽高的圆点、圆钮）；**胶囊**。胶囊写 `radius.bubble`（24）而**不写 `999px`**——≤48px 的盒子上 CSS 会把半径收到半高，与 `999px` 渲染逐像素一致，而无穷大的圆角会触发 WebKit 的合成伪影（`PITFALLS §1.1`，该条的处置原文就是"圆角用安全值 24px"）。行/钮的胶囊有两种等价写法，取其一：`var(--dsh-radius-bubble)`；或 `calc(<自己那个高度变量> / 2)`（输入胶囊用后者，因为它的高度与圆角派生自同一个变量 `--composer-h`）。
| 边缘高光 | 不用独立 token | 顶部高光由 §1.4 三档投影里的 `inset 0 1px 0` 层承担；亮色改用 1px 底缘接地线 |
| 窗口阴影 | 系统提供 | 原生窗口/面板 |

**投影只有三档**（数值在 `theme.css` 的 `:root`，两套主题各一份配方）：

| 变量 | 落点 |
|---|---|
| `--shadow-card` | 贴地卡：主卡 / 会话卡 / 右侧面板卡 / 代码块铬件 |
| `--shadow-pop` | 浮在内容之上：菜单类浮层、右键菜单、命令面板、流内卡（工具/审批/提问） |
| `--shadow-modal` | 对话框与灯箱（更深一档；落点是近实色 `--panel-strong`，不吃"重投影描黑低透明边界"那条约束） |

亮色另立配方（1px 底缘接地线 + 更浅更远的环境投影）——暗色那套的顶部白内高光在亮色下等于没有，黑 .20 落在近白卡上会发闷。**不属于档位、就地写的**：键帽底缘微投影、PDF 纸页、内高光。新表面选一档，别再就地写第四套。

**同心圆角**：两个圆角相邻且同时看得见时，内圆角 = 外圆角 − 两者的间隙（`radius.panel 18` 就是从 `window 26` 减 8px 缝来的）。跟着它有两条优先级：

- **对齐控件优先于同心。** 浮层挂在某个钮上时，先让它的边缘与那个钮对齐，圆角落在哪儿就是哪儿——2px 的半径差在角上几乎看不出来，2px 的边缘错位一眼就是"padding 坏了"。
- **要合上差额就改间隙，不要改曲线。** 一个半径被多个面共享（`radius.floating` 同时是模型菜单、命令面板、浮层的角），位置常量不是——改间隙影响一处，改半径影响一片。

同心只在两个角**真的相邻可见**时成立：列表行上下是浮条、与面板的角不共处，`radius.card 14` 是为行自己的体量选的，不要为了凑同心把它抬到 18。

**材质来源＝系统液态玻璃**（`-apple-visual-effect`，Raycast 同一条路）。做法统一：浮面本体只留几何与外投影，材质全在**材质层**（`<GlassLayer />` / `[data-liquid-glass-backdrop]`，见 §2.2bis 的五条硬约束）；材质层由宿主的**材质族**参数化（`theme.css` 的材质族预设块与各 module 里的同名两项，一处在 theme.css、模块面在各自文件）：

| 族 | 底色 tint | 回退模糊档 |
|---|---|---|
| 瞬时浮层（菜单 / 提示 / 选择器 / 下拉） | `--panel-glass` 真半透 | `--blur-float` |
| 对话框（设置族弹窗 / 项目弹窗 / 引导卡 / 游戏面） | `--panel-strong` 近实色 | `--blur-scrim` |
| 命令面板 ⌘K | `--panel-palette` | `--blur-float` |

**材质层没有装饰**：不描边、不勾内缘高光——面的范围由底色承担（用户 2026-10-14 定稿，见 PITFALLS §5.20）。全站只有输入胶囊那一族（`.composer` / `.mini-controls`）给自己写 `--glass-inset: var(--composer-shadow)` 那两条 inset 内缘高光，其余面一律 `--glass-inset` 缺省（= `none`）。

回归档（系统材质不可用时自动落回）：`-apple-visual-effect` 在 `@supports` 里，关着就是材质层上那份 CSS 模糊——**所以模糊档与 tint 仍要写全**。

**系统材质档里底色与 CSS 模糊一并撤下**：上表的 tint 是**回退档**的值（真半透/近实色，为「自带模糊」配的），`@supports (-apple-visual-effect: …)` 里换成 `background: none` + `backdrop-filter: none` + `-apple-visual-effect: -apple-system-glass-material`（输入胶囊与迷你控件簇取 `-media-controls` 档，对应参考实现的 AI 输入底栏）。为什么不是"垫一层轻色更稳"：底色画在材质**之上**，垫一层就是把玻璃盖死——见 PITFALLS §5.16。一条开关写在**属性**上（不是变量），所以 CSS Module 的哈希类名也照样命中。两条轴的分野按"这个面是瞬时的还是承载内容的"：瞬时用真半透（它只浮一下，用户要看得见底下的位置感），承载内容用近实色（里面有正文要读，底下是壁纸时正文才读得清，同 §1.5）。**不许再出现第五套 blur 数值**：全仓 `backdrop-filter` 只引 `--blur-veil/-float/-glass/-scrim` 四个变量。
**窗口失焦**：材质退 `-subdued` 档（`html[data-window-blur]`，`windowFocus.ts` 维护）——参考实现在 `[window-blurred]` 下同样降级；不降的话失焦窗口里的玻璃会继续按自己的采样亮度发亮，读起来像"这个窗口还活着"。

**不接系统材质的一族（内容区例外）**：文件预览浮窗、会话卡与右侧边栏面板卡、迷你命令中心卡——它们承载大块正文，底色取近实色或由壳的原生玻璃垫底（`SPEC-SEMANTICS §6.1`），换玻璃会牺牲可读性；这一族的面**不要**加材质层。

**层级只有四档**（`theme.css` 的 `:root`，顺序即语义）：`--z-scrim` 1000 < `--z-menu` 1100 < `--z-tip` 1300 < `--z-top` 2000。**遮挡垫必须低于菜单**——对话框里点开的下拉是挂 body 的，垫子高过它就把菜单压在自己底下、连点击都被垫子接走。留在组件内部的浮层（composer 菜单、迷你面板卡、卡内徽标）用组件自己的层级，不入档：它们的 z-index 只在自己那个堆叠上下文里有意义。

**网页里的系统玻璃**：`[data-liquid-glass-backdrop]` 那一层（`-apple-visual-effect` + 私有 `useSystemAppearance` 门）的完整约束、材质板几何与事故见 `PITFALLS §1.20`；五条硬约束见 §2.2bis。

### 1.5 材质与 Vibrancy（玻璃窗口）

- 窗口底板（`WindowGlassView`，坐在所有内容之下）：**macOS 26+ 用 Liquid Glass**（`NSGlassEffectView`，style `.regular`）；更早的系统退回 `NSVisualEffectView`（material `.sidebar`，Blending `.behindWindow`）＋ 近黑 tint。两形态职责相同、观感不同。
  - 为什么必须显式创建：整个界面画在透明 `WKWebView` 里、不是标准 AppKit 控件，拿不到系统对标准控件自动发放的液态玻璃；CSS 也补不上——`backdrop-filter` 只采样 webview 内的网页内容，采不到下面的原生层。
  - 材质取语义名而非 `.hudWindow`——后者是"浮在其他窗口之上的 HUD 面板"档案，与"窗口的底"不符。
- **窗口必须 `isOpaque = false` + `backgroundColor = .clear`**：底板采样的是窗口背后的桌面，不透明的窗口只能退化成"窗内混合"的平灰（AppKit 不会因为 contentView 是玻璃视图就自动改，见 `PITFALLS §4.27`）。
- tint 只定基调，玻璃观感归玻璃：两条分支的档位见 `WindowGlassView`（退回分支以 `surface.panel` 为准；液态玻璃自带亮度，tint 只往近黑拉一档）。压到近实色（≥.8）等于把玻璃盖死。
- Web 侧表面色用 1.1 半透明值透出材质；**内容区例外**：`.main`/会话卡/右侧面板卡（`--card-gradient`）取近实色——底下是用户壁纸时正文才读得清。
- **外观所有权两条（2026-10-12 采纳，源自 Atd 对照调研提案 #2①②）**：
  - **窗口外观归底板一格所有**：裁角、外描边、投影、桌面混合只由 `WindowGlassView` 绘制，web 层不画"窗口壳"——`html`/`body`/`#root` 保持透明填满（`PITFALLS §1.5`）；页面里出现第二份**窗口级**外圆角/外描边/外阴影即重复所有权。浮层（菜单/弹窗）自带圆角与投影是它们自己的盒，与此条无关（§2.4）。
  - **一层 fill 只有一个 owner**：同一表面的 tint/fill 只许一层承担——底板 tint、web 根、元素、伪元素里挑一处，不许叠（`PITFALLS §4.27` 根因④的 `.app` 白纱是反例，已删）。
- 玻璃细节：`surface.raised` ≥62% + 顶部高光（投影档的 inset 层）+ 对应投影档。

### 1.7 动效

**先归类，再取值**：任何动效只属于三类之一——**位移**（元素在两处之间移动：边栏推让、选中滑移）、**显隐**（到达或离开：浮层、菜单、面板、大件展开）、**反馈**（即时小状态：hover/按下/淡入淡出）。同一类全 app 同一配方——到处用同一小组值，感觉才像一件软件而不是一堆视图（照参考项目 Search 的 `Motion.glide/settle/quick` 三词汇模型，见 `REF-BROWSER-SEARCH.md`）。

**词汇就这些**：数值在 `theme.css` 的 `:root`（唯一数值来源），场景对应在下表。**新写动效只引变量，不手写字面量**——散落的 `100/140/160/180/260/320/350/380/500ms` 与六条曲线已于 2026-09-30 全部收回（TODO §18b）；曲线只认 `--ease-out` / `--ease-spring`，裸 `ease`/`linear` 不出现在过渡里。

**梯度按参考实现校准**（`~/tools/raycast-motion-spec.md`）：微交互 150ms、位移 200ms、内容 300ms——`--dur-fast` 因此是 150ms 而不是 120ms。两条曲线也取自该参考的形状：`--ease-out` 是 ease-out-expo（强减速做入场）、`--ease-spring` 是 ease-out-back（过冲做俏皮回弹）。

**明确不采纳的一条**：参考实现里"macOS 上微交互零过渡"（悬停反馈瞬时生效、刻意不做 transition）。本仓的行/钮 hover 走 `html[data-hover-armed]` 门控（§1.10），门控本身就是"指针移进来才亮"的机制，再叠一层零过渡会让悬停反馈与门控的时序打架；保持 `--dur-fast` 过渡。

| 变量 | 用途 |
|---|---|
| `--dur-fast` | 控件态：hover/按下/淡入淡出/小位移 |
| `--dur-med` | 结构位移与显隐：左右边栏推让、浮层与菜单、面板开合 |
| `--dur-slow` | 大件展开收起（思考过程折叠、行高与网格过渡） |
| `--dur-slowest` | **全 app 唯一一处**：启动交叉淡入（骨架屏 → 界面） |
| `--loop-breathe` | 常驻循环：状态点呼吸（running/waiting） |
| `--loop-spin` | 常驻循环：转圈类加载 |
| `--ease-out` | 位移与离场曲线（进场也用它的那一档：流内内容） |
| `--ease-spring` | 带回弹，**只给"内容"的入场**：引导卡、侧栏项目名让位 |
| `--ease-pop` | 浮层进场的唯一曲线（照参考实现的 popover：`.3,.7,0,1.26`，尾端一点过冲）；离场用 `--ease-out`——快出慢入 |

| 场景 | 配方 |
|---|---|
| 控件态 | `--dur-fast` + `--ease-out` |
| 结构推让（左右边栏） | 位移 `--dur-med` + `--ease-out`，淡出 `--dur-fast`；**进退同一对值**（transition 两头都跑，不做"进场有、收场没有"） |
| 浮层 / 菜单 | 进场 `--dur-med` + `--ease-pop`（opacity .6 ＋ scale .97→1）、离场 `--dur-fast` + `--ease-out`；配方只有一份（`@keyframes pop-in`/`pop-out`，见 §2.2ter），逐面只定 `transform-origin` |
| 大件展开收起 | `--dur-slow` + `--ease-out` |
| 流式文本 | 无逐字动画；上插淡入 `--dur-fast` |
| 状态点 running/waiting | `var(--loop-breathe)` 呼吸；`prefers-reduced-motion` 全静止 |

- **延迟是编排量**：`animation-delay` / `transition-delay`（错落入场的步进）按场景就地写，不进词汇。
- **停留时长按"要读还是要瞄"来定**，不随手写：文字反馈要留够读完一句（`ToastBar` 3s，§2.1）；状态/数值一眼即可（行内「已复制」反馈约 1s）。**同一个交互只该有一个值**——同一个「已复制」现在 `CodeBlock` 是 1.2s、`DiffBlock` 是 1.0s，是待收拢的分叉。
- **进行中的提示没有天然停留时长**（转圈、进度、展开态），由发起方负责收起，不设自动消失。
- **常驻循环分两种**：状态点呼吸、转圈加载**只引** `--loop-breathe` / `--loop-spin`（同族状态点/转圈必须同拍）；质感动画（微光 shimmer、骨架脉冲、eq 跳动、文件旋转）各有自己的周期，就地写——它们不是交互延迟；但别再新增第五种交互时长。

1. **没有解释性文字**：每个文案只有一个职责（标题/动作/占位/分组标签），无副标题、无说明句、无"以下""你可以"。

### 1.10 悬停与光标（hover & pointer）

> 依据（一手资料）：Raycast 技术深潜的 *Platform conventions* 两条——"**No cursor: pointer on interactive controls.** Desktop apps don't do this; **it signals a website.**" 与 "No hover highlights **on most** controls."（后者的限定词是 *most*：禁的是"像网页那样"的高亮，不是 hover 本身。）

**光标**：手形只给正文里的超链接（渲染出的 `<a href>`，浏览器自带），其余一律箭头。`theme.css` 顶部那条 `* { cursor: default !important }` 就是这条口径的执行者——**不要再往控件、行或披露头上加 `cursor: pointer`**。行和披露头上挂手形是最容易被认成网页的一处，加回来等于把这条作废。

**hover**：行/列表项/菜单项的 hover 只响应"指针主动移动过来"，不响应"指针恰好停在这里"。指针不动而列表滚动、流式内容重排、或浮层刚好在它底下打开时，滑进来的那一行不该亮——那不是指针选的。

- **门控**：样式侧 `:where(html[data-hover-armed])`（`theme.css` 与各 `*.module.css` 的行/菜单规则都带这道前缀；用 `:where()` 是为了**零特异性**，不加它的那条 `xx.selected:hover` 之类的优先级关系不受影响）。机制侧 `frontend/src/hoverArming.ts` + `main.tsx` 里的一次 `installHoverArming()`。复位只改根属性，CSS 自己就把已亮的行熄掉，不走 React 重渲染。
- **容差 3pt**：滚轮点一下会让鼠标挪一两个像素、手势结束还会补一个零位移的 `pointermove`，都不到这条线。**锚点只在点亮时才移动**，所以一像素一像素地蹭也会累积；**复位时锚点落到指针当下所在**——滚动时手在滚轮上的抖动永远累积不起来。
- **复位时机**：滚动（`scroll` 捕获阶段，含流式输出钉底时的自动滚动）；换视图（换会话/换空间/开关设置浮层）；⌘K 命令面板打开。判据是"内容在指针底下换了身份"，不是"用户做了什么"。
- **门控范围**：行、列表项、菜单项，以及这些行上 hover 才现的控件（置顶/归档/箭头）。**一直在那儿的控件不门控**——按钮、图标钮、chip、关闭/返回/发送这些不随内容滑动换身份，hover 反馈照旧。
- **行的 hover 填充引 `--row-hover`**（比 `--fill` 轻一档），且恒轻于 `--selection`：hover 是"指针在挑这一项"，不能盖过"这一项被选中"。选中压过 hover（`.task-row.selected:hover { background: transparent }` 那对规则就是它）。

### 1.11 悬浮注释（Tooltip）

任何元素挂 `data-tip="文案"`（可选 `data-tip-keys="⌘,"` 键帽、`data-tip-pos="top|bottom|left|right"`）就有注释；宿主组件是 `components/Tooltip.tsx` 的 `TooltipHost`，注释本体是同一份 `TooltipChip`。

**两条宿主，同一份本体**：

- **壳内（mac）＝独立窗口**。注释住在一块透明无边框面板里（`Tooltip/TooltipWindow.swift`），窗口贴着一块 `?tooltip=1` 的透明 webview（只渲注释本体）。页面**不画注释**，只把锚点矩形推上去（`tooltip-show`/`tooltip-hide`）；落位（偏好边居中 → 放不下翻面 → 夹进屏幕可视区）与开合全在壳里（`TipPlacement` / `TooltipController`）。**窗口不垫原生玻璃**：材质与输入胶囊是同一份 CSS 系统玻璃（`[data-liquid-glass-backdrop]` 那条全站规则，见 §2.2bis），两层玻璃叠着会发灰。窗口留着是为了另外两件事——**原生 AppKit 控件那一族（截图/标注工具条）只能走它**（CSS 到不了 AppKit 视图，`NativeTooltip`），以及它一块就能按屏幕坐标同时服务主窗/迷你面板/命令中心卡三块页面。
- **页内（浏览器调试 / 没有那条壳能力的平台）**：`TooltipHost` 在页里 render 一份同款注释，自己落位、自己出材质（`--panel-glass` + blur + `--shadow-pop`）。走哪条路由 `platform.ts` 的能力位 `tooltip` 决定。

**几何**（Raycast tooltip 口径）：内距 6、内容间距 4、`max-width` 300，文案自带 4px 横向内距；形状是**胶囊**（与全站胶囊语法统一，用户定稿）。键帽吃 §1.8 的**有底**那一档（Raycast 的 `prominent`：底 fg-10 + 主文字色）。

**动效**（Raycast popover 口径，"快出慢入"）：打开 `.25s cubic-bezier(.3, .7, 0, 1.26)`（尾端一点过冲），`opacity .6 → 1` 且 `scale .97 → 1`；关闭 `.15s ease-out` 到 `opacity 0` / `scale .97`。页内那份跑 theme.css 的 `tip-in`/`tip-out`，壳内那份由原生窗口跑同一条曲线（`TooltipWindow` 的组动画）。

**原生控件也走这一套**（截图/标注工具条那一族，`Capture/Annotation/`）：`NativeTooltip` 把"哪个控件 + 文案 + 键帽"算成屏幕矩形喂给同一块注释窗口（控件侧只需 `HoverReporting.attachTooltip(text:caps:)`，指针进出的跟踪区见 `PointerTracking`）。两条口径：① **注释必须浮在被注释窗口之上**——截图 overlay 住在 `CaptureOverlayPanel`（`.screenSaver` 档），注释窗口按被注释窗口的层级现算（`TooltipWindow.raise(above:)`，普通窗落回默认档），不抬上去是"整块被盖住、而且不报错"；② **系统原生 `toolTip`（那种小黄标）不用**，挂过它的控件一律改挂 `attachTooltip`——全站注释只有一套语言。

**时机**：悬停立即弹；滚动 / 按下 / 移出 / 目标元素离开文档即收；壳内那份另加一条"应用退到后台就收"（注释浮在所有窗口之上，跟着跑到别的应用头上没有道理）。**"移出"的判据要排除指针挪到了触发元素自己的子节点上**（图标钮里从钮挪到钮里那颗 svg 是同一个动作单位，`mouseout` 却照样打在钮上）——漏了这条，图标钮上轻轻一动就收起再弹出，观感是"抽搐"（用户 2026-10-13 报；锁在 `__tests__/tooltip-hover.test.tsx`）。文案规则见 §1.9 第 9 条（短动词词表）。

**注释与自己的 hover 浮层互斥**：同一个元素**不要既挂 `data-tip` 又挂一张自绘的 hover 卡**——注释是壳里那块独立窗口渲染的，卡片是页里的浮层，两者互不知情，指针一进去就同时冒出来。要卡片就别要 `data-tip`（可访问名走 `aria-label`，`UpdateBadge` 与 `UsageMeter` 的环都是这么做的）；要注释就别要卡片。带 `data-tip` **又**点开浮层的先例（思考强度选择器、模型的 ⓘ 详情卡）是**点击**开，不冲突。

- **输入胶囊的材质在分离层 `[data-liquid-glass-backdrop]` 上**（内容与材质分离，Raycast 同款结构）：胶囊本体只有网格/内距/单行高/圆角，**底色 `--composer-bg`（tint，只定基调——铁律见 PITFALLS §7 玻璃那条）、投影（只许 inset 内缘高光）、材质在这一层**（`position:absolute; inset:0; border-radius:inherit; pointer-events:none`，铺满胶囊）。**外投影 `--composer-drop` 留在胶囊本体**：系统材质是「托管材质」（`HAVE_MATERIAL_HOSTING`），WebKit 自动建的结构层 bounds ＝ **元素自己那层**的 bounds（`GraphicsLayerCA::updateGeometry`；圆角只读元素自身的 `border-radius`，没有任何 CSS 钩子），元素层带**外扩**投影时 bounds 会被撑大 → 材质板比胶囊每边大一圈（实测暗色下多出 ~17px ≈ 那条 `0 4px 12px` 的扩散量），所以材质层上不许有外投影。材质三档：macOS 26 起经 `@supports` 换成 `-apple-visual-effect: -apple-system-glass-material-media-controls`（系统合成器渲染液态玻璃、CSS 模糊撤下，两套玻璃叠着会发灰）→ 退回 `backdrop-filter: blur(24px) saturate(150%)`（WebKit 需双前缀）→ 退到底色，所以材质画不出来时胶囊仍是一块读得清的面。z 走 `0` + 内容层抬到 `1` 分先后（**不用 -1**：负 z 会逃到最近的栈上下文、画到宿主祖先的背景底下，悬浮卡那一页会整块消失），因此**不要求宿主做成栈上下文**。**成立前提是宿主干净**：`.composer` 及其祖先不许有 backdrop-root 触发器（`backdrop-filter`/`filter`/`opacity<1`/`mask`/`clip-path`/`transform`/`perspective`/`contain:paint`/`isolation:isolate`）——有一个就把子层采样锁进宿主内部、只剩底色＝一块实心（浮层配方③；2026-09 那两轮"子层不可见"的真因就是宿主自己挂着 blur、以及 pop-in 动画残留的 transform，不是"WKWebView 不渲染子层"）。浏览器悬浮卡那一页（另一块 webview）CSS 模糊本来就采不到面外内容，那一档由壳的原生磨砂兜着。**系统材质那一档要壳配合才亮**：`-apple-visual-effect` 在 WebKit 里带 `settings-flag: useSystemAppearance`（默认 false），关着时属性连解析器都不认识（`CSS.supports` 全 false、声明被丢弃）——开关在 `Support/WebKitSystemAppearance.swift`（主窗 / 迷你面板 / 悬浮输入框三处 webview 各开一次，走私有 `WKWebView._setUseSystemAppearance:`；浏览器页是别人的内容，不开；App Review 2.5.1 只认公开 API，本应用走 Developer ID 自行分发）。本机实测（macOS 27 / 26A428）：开启后同一段 CSS 的 computed 值从 `""` 变成 `-apple-system-glass-material-media-controls`。它是"网页内容里拿系统玻璃"的唯一入口——原生 `NSGlassEffectView` 糊不到同一块 webview 里的内容（PITFALLS §4.38）。**这条也是「材质层」机制本身的规范**：任何要系统玻璃的表面都照它办——宿主留几何与外投影（`--composer-drop`）、挂一个 `[data-liquid-glass-backdrop]` 子元素，层上只放底色（**不描边、不勾环**；只有输入胶囊那一族另给自己两条 `inset` 内缘高光，见 §2.2bis 第 3 条），圆角写**实际值**（`inherit` 到 999px 会把一个给不出形状的数喂给 SwiftUI）。现役两处：输入胶囊（主窗/草稿页/迷你面板/悬浮卡共用同一个 `Composer`）、迷你面板右上角的控件胶囊（`.mini-controls`）。

- **附件胶囊不描边、靠底色分层**（用户 2026-10-14 定稿："不要用描边，还是用颜色来区分"）：`--fill-strong` 底 + 两端全圆，与输入胶囊同一块玻璃上的一颗、和页内查找那颗同一套语言。失败态也不改底色——名字右边那截红字 + 一颗「重试」已经把话说清了（底色是"这是一颗胶囊"的语言，不借给状态）。
- **思考强度档位是输入框自己的控件，与模型选择分开**（用户 2026-10-09 定稿）：模型菜单（会话头/会话设置/草稿页头部三处）**只选模型**——没有档位第二层、没有档位标签；档位是输入框右簇里那颗胶囊（`composer/EffortPicker`），显示引擎给的档位名。**显示口径**（用户 2026-10-10 定稿）：有引擎报的生效档就显示它；没有则显示档位表里**最高**的一档——**任何情况下都不显示为空**，也没有 `Default` 这种假档位名。引擎侧已同时改掉根因（`llm-pi-ai` 的 `describableReasoningLevel` 兜底到模型支持的最高档，且请求路径复用同一解析，所以目录报什么就是真跑什么），前端这条只是第二道保险。完整事故与验证方法见 `PITFALLS §7.11`。点开是单选弹层（`.ddMenu/.ddItem`，复用设置页配方）、**默认贴上方**（输入框贴底，向下开必出屏），选中项打勾、点选即提交并关闭。`⇧⌘E` 循环到下一档，输入框聚焦时也生效。**模型没有 reasoning 元数据时整颗胶囊不渲染**（不是置灰）。胶囊**无底色**：hover 与展开态只把字提到 `--ink`，不给填充块——右簇里凭空多一颗带底的胶囊会跟发送钮争重量；档位名也**不套截断/省略号**（配 `line-height:1` 会把下伸部切平，看着像半个字被削了）。右簇三颗（档位 → 容量圈 → 发送/停止/听写）是同一个 `.composer-actions` flex 簇，簇内间距 12px（比输入框那条 4px 宽一档，否则读成一块）：单行态右对齐、宽态整簇换到底部行右对齐。
- **附件一律 chip，没有大小上限**（用户 2026-10-09 定稿）：文件不做 chip，用户心智就断了（曾经一度把非图片文件改写成 @ 路径文本，用户否掉：那是曲线救国）。上限只出现在「能不能」两处——图片 > 32MB 没法内联（改按文件附件发，chip 照旧）；桥的单请求**缓冲**上限超了就落临时文件再流式转发（**不是拒绝**）。页面手里有字节的走 XHR；只有路径的（选择器挑的大文件）由壳 `EngineGateway.uploadFile` 按块读盘直送引擎；文件夹没有字节可传，只能 @ 引用。

### 2.2bis 材质层的五条硬约束（用 `GlassLayer` 前必读）

浮面接系统材质＝在本体里放一枚 `<GlassLayer />`，然后逐项核下面五条。任一条没做到，表现都是"这块浮面看着不对"，不报错、测试不红：

1. **宿主必须自己定位、且带显式 z-index**（＝栈上下文）。材质层用**负 z** 垫在宿主内容之后（照参考实现的 `chat-panel-glass`），内容层因此不需要任何定位或抬升。代价是负 z 只在宿主是栈上下文时才被关在宿主里——只有 `position` 而 `z-index: auto` **不算**，材质层会逃到祖先的背景底下、整块面消失（PITFALLS §5.17，实测在 `.composer` 上抓到过）。**这条由架构检查器的 `glass-host` 规则守着**。
2. **宿主不许有自己的底色，也不许挂 `backdrop-filter`**。底色画在材质**之上**，垫一层就是把玻璃盖死——2026-10-14 报的"不像玻璃／一块平灰"就是这个；磨砂叠在材质上会发灰（PITFALLS §5.14 / §5.18）。要调节只许动 `filter` 的 `saturate/brightness`。
3. **材质宿主一律不描边、装饰也不进材质层**：面的范围由**底色**承担——不画线、不勾 `inset` 内缘高光（用户 2026-10-14 定稿，PITFALLS §5.20）。参考实现的分工是"影留宿主、材质层只出材质与底色"：托管材质的板按材质层自己的 bounds 铺，任何外投影挂在材质层上都会把板撑大一圈（见 `--composer-shadow` 那条注释），所以外投影写宿主。全站唯一的例外是输入胶囊那一族自己的两条 `inset` 软高光（`--glass-inset: var(--composer-shadow)`，不外扩、不是线）。**这条由架构检查器的 `glass-host` 规则守着**（宿主规则里出现非 `none` 的 `border` 即失败）。
4. **回退链要写全**：材质属性在 `@supports` 里（它要壳的 `useSystemAppearance` 私有门，见 §1.4bis 末），门外那份 CSS（真半透底色 + `--blur-*`）必须留着——拿不到材质、或材质没托管成功的运行时靠它读得清。材质可用时才把底色与 CSS 模糊一并撤下（见 §1.4bis 的材质族表）。

### 2.2ter 浮层宿主：两个原语（`Popover` 与 `Modal`）
5. **挂的粒度是"每处渲染"，不是"每个类名"**：同一个类（`.ctx-menu` / `.ddMenu` / `.dialog-card` / `.panel-browser-offers`…）有几处 JSX 渲染，就要有几枚 `<GlassLayer />`——宿主只留几何之后，漏挂的那处就是**一圈描边加一片透明**。遍历检查按"类名 → 全部渲染处"做，别按"类名存在性"做（PITFALLS §5.16 记了三次同型事故）。


浮面的**壳**只有两个，别自己拼第三个：

| 原语 | 管什么 | 用在哪 |
|---|---|---|
| `components/Popover.tsx` | 贴触发器的浮层：portal 挂容器、按触发器（元素**或一条矩形**）算位置（`side`/`sideOffset`/`align`/`alignOffset`：放不下自动翻面、越界收敛、限高）、外点/Esc/窗口 resize 关闭、`data-state` 进出场、材质层 | 菜单、下拉、选择器、旁位卡（模型基准详情卡贴在菜单左侧——横开也是 `side="left"`） |
| `components/Modal.tsx` | 盖在应用之上、屏幕居中：遮罩（`--z-scrim` + `rgba(0,0,0,.45)`）+ 居中卡片 + 同一套关法与进出场 + 材质层 | 对话框、命令面板、游戏面、引导卡 |

调用方只给**内容**与**几何**（宽高、内距、布局写在它自己的类里）——圆角/描边/投影/材质/动效/关法一律归原语。进出场是全站唯一一份配方（`theme.css` 的 `@keyframes pop-in` / `pop-out` + `--ease-pop`，数值照参考实现的 popover）：进场 `--dur-med`、离场 `--dur-fast`（快出慢入）；**进场 `fill: backwards`**（`both` 会把末帧的 transform 永久留在宿主上，见 PITFALLS §1.10）、离场 `both`（要停在隐藏态等 JS 摘 DOM）。

**刻意不用这两个原语的浮面**（它们不是"量一次就摆好的弹出菜单"，但**共用同一份材质层与投影配方**）：

| 面 | 为什么不用 |
|---|---|
| 输入胶囊 / 迷你控件簇 | 材质层就长在自己身上——常驻的一颗胶囊，没有开合与触发点 |
| composer 的 @·/ 菜单 | 绝对定位挂在 `.composer-anchor` 下、**不能** portal（`.composer` 自己是一块模糊面，portal 出去就采不到面外内容），宽度还跟随输入框 |
| 地址栏补全（`BrowserAddressField`） | 锚点在**持续移动**（胶囊有宽度过渡、标签行会横向滚），摆位要跟着 ResizeObserver/scroll 重算，不是量一次就完 |
| 划词浮条（`SelectionActions`） | 收敛边界是**消息流卡**的矩形而不是视口，且要按浮条实测尺寸钳位 |
| 页内查找胶囊 / 断线横幅 | 常驻在页面里的一枚定位元素 |
| 图表提示（`ChartTip`） | 跟指针走 |
| 灯箱 / 文件预览浮窗 | 全屏或近全屏的独立浮窗（蒙版与几何自成一套，见 §1.4bis 的"不接材质的一族"） |

### 2.3 键盘映射

**应用内快捷键的事实源是 `frontend/src/keybinds.ts`**：`KEYBIND_DEFS` 七条可改键（新建会话 `⌘N`、侧栏 `⌘B`、听写 `⌘D`、思考强度 `⇧⌘E`、设置 `⌘,`、搜索 `⌘K`、页内查找 `⌘F`），`FIXED_KEYBINDS` 是各交互面与浏览器页面、macOS 菜单接管的固定键位——两表都由设置→快捷键直接渲染，本文不再另抄一份（改键位改注册表）。

交互面内的固定语义：`Esc` 收起菜单/取消 · `Enter` 发送 · `@` 引用 · `/` 命令 · `Tab` 补全（候选列表内 `↑↓`/`Enter`/`Tab`）；全局 `⌥Space` 唤起面板、`⌥1-9` 切项目空间（按**物理键位**判断，见 PITFALLS §4.29）。

**页内查找（`⌘F`）**：会话流右上角一枚胶囊（输入框 + 上一个/下一个 + 关闭；材质与"回到底部"钮同一档——**无描边、靠底色分层**，输入框与胶囊**同一块面**、不另给底色/圆角，用户 2026-10-09 定稿：不在胶囊里再嵌一层框），命中用 CSS Custom Highlight 画在只读的流上——**不改 DOM**。两档：全部命中 `--fill-heavy` 淡底，当前命中 `--ink` 反色（黑白高亮法）；`Enter`/`⇧Enter` 走命中并滚到视野中央，找不到给"没有匹配"，`Esc` 关闭并撤掉两档高亮。引擎没有 Highlight API 就不开这个入口（能力探测降级）。

### 2.4 弹层材质 / 品牌图标 / 设置卡片（2026-09 定稿，来自模型页事故）

- **弹层材质**：**查 §1.4bis**；两条硬纪律不变——`backdrop-filter` 必须 `-webkit-` 与标准**成对且 `-webkit-` 在前**（压缩器反过来会把标准条合并掉，`PITFALLS §1.8`），且禁止恢复全局 `* { backdrop-filter:none !important }` 核弹 + 白名单机制。新弹层自带 blur 即可；`.flow *` 的禁用保留（合成隔离，弹层不挂 flow 内）。
- **品牌图标（提供方 logo）**：全部**单色反白**（`fill=currentColor` 随主题），禁品牌彩色、禁白底/彩底 chip。来源顺序：`@lobehub/icons-static-svg`（AI 提供方全覆盖，`?raw` 内联 svg）→ `simple-icons` 单色 → 首字母 monogram。**禁用 React 内联 style 传 `maskImage`**——存在静默丢弃，`?raw` 内联 svg（自带 fill=currentColor）最稳（PITFALLS §1.9）。
- **卡片 vs 描边（用户定稿，2026-09-12）**：**有底色的卡片一律不描边**；确实需要描边的（贴边浮层等），**里外颜色必须一致**（描边只勾边、不换底）；流内**提醒条两端做胶囊**（`radius.bubble` 24，勿用 999px）。
- **分组卡片**：卡片**无描边**，纯底色区分范围（`var(--fill)`）；行间分隔线用缩进 `::before`（左对齐文本、右留空），**禁全宽横线**；区块标题与内容间距 ≥12px（标题贴内容为反复出现的回归）；**页面头已有大标题时，卡片内不再重复同级标题**（2026-09-04 快捷键页"快捷键"×2）。
- **Meta 胶囊与数值**：标签胶囊只呈现引擎真实数据（reasoning / 额外输入模态 / 上下文窗口），缺的属性不编造；`text` 是每个模型的默认能力、不占标签，模态来源字段 pi 是 `input`、DeepSeek 是 `inputModalities`（别互相代用）；数值紧凑化（1000000→1M、131072→131K）。
- **手写路由的模型自带默认思考档位**：`llm-pi-ai` 的条目只在声明了 `reasoningEfforts` 时才被引擎当成能推理的，而自定义路由（自定义 baseURL）在安装目录里没有条目可继承——不补这一项，模型进引擎就是"不支持推理"，输入框的档位胶囊永不出现（`PITFALLS §7.13`）。所以新建手写路由的模型时补一套 `{low, medium, high}`（档位名即线上取值）；预置路由不补（那类有安装目录条目可继承）。

**模型弹窗（2026-09 定稿，照参考图）**：字段面＝提供商 → 接口地址（自定义）→ API Key → 模型名称 → 高级配置（提供方 ID / 协议 / 视觉）；说明只留真正改变行为的那一条（模型名称下方「留空则添加该提供方的全部模型」），且写成一句软件提示、不写「A＝X；B＝Y」式规格口气，能从界面自明的（按接口地址推导的名字摆在占位里、协议有默认值）不再写一行解释；不出上下文窗口与显示名称，模型类型只给引擎真能兑现的「视觉（图片输入）」。
- **新建项目弹窗（2026-09 定稿）**：**壳、字号、控件规格与添加模型弹窗完全同源**（复用 SettingsRows 的 modal/rowGroup/rowCard/按钮类——标题 `lg`、输入 30 高 `base`、按钮 28 高；自定大字号被否决），字段面＝名称（必填，行尾内嵌图标触发钮）→ 审批模式 → 工作区文件夹（textField 同规格按钮「＋ 选择目录…」）→ 项目指令（可选 textarea，说明并入标签旁 ⓘ）。审批行绑定**应用级**设置（引擎 `permission.defaultPreset`，与设置页同源同义；引擎未提供时隐藏）——项目级化需引擎扩展，另行立项。工作区文件夹留空由壳在 `~/Documents/DeepDive Projects/<净化名>` 自动建（引擎 workspace/create 要求目录已存在，建目录只能壳做；撞名追加序号）；名称与目录末级名不同才走 workspace/rename；指令由壳写入 `<项目>/AGENTS.md`（引擎按 cwd 读），已存在不改动。图标选择器＝搜索行 + lucide 精选集（~46 个，含「默认（首字母）」复位项），portal 菜单复用 `.ddMenu/.ddItem` 配方（显式 min-width 压掉类的 `min-width:100%`）、放不下向上翻；选择按 workspaceId 存 localStorage（`deepdive.ws.icon.<id>`，桥端口已固定），显示优先级 glyph > 根目录约定图标文件 > 首字母，删除工作区同步清 key。浏览器（无壳桥）降级＝工作区文件夹手输路径（promptDialog）、指令字段不出现。

  - **渐变形状头像**（在跑的行，用户 2026-10-12 定稿）：**委派身份串**哈希定的平面双色小块——身份=引擎给子会话登记的 label（= `subagent` 工具参数里的 `description`，"专给显示用的短描述"），会话流工具行/面板行/胶囊堆叠三处共用同一身份（同日更正：原先三处各拿各的 id，同一个 agent 三套颜色形状）。渐变是**平涂线性对角**（135°，主色→伴色直线过渡、无高光；错位双团被否"还是有高光"），S 36–48、主色 L76/伴色 L68（"更亮一档"定稿）；**形状 7 种圆角**（圆/圆角方/三角/菱/五边/六边/squircle）也随身份，多边形 clip-path 按 size 现算（`polygonPath`），形状派生用加盐重散列（`seed#shape`，防同前缀短 id 坍缩）；边缘薄雾由 `theme.css` 的 `.agent-orb` 遮罩收出（实心到 85% 再淡出）。约束随机（色相全轮、饱和/亮度/偏移锁带）不出脏色，同一子智能体永远同色同形、跨重启稳定；无动画；配色形状渲染同居 `AgentOrb.tsx`（纯函数直考）。已结束的行不用头像，仍是对勾（勾本身即状态，不带色彩语义）。

  - **委派行的文案**（同日定稿）：摘要=身份串首行（`agentSummary`），**整段提示词不上行**（通用 `summarizeArgs` 的键序里 prompt 排在 description 前，直接用会把系统提示词摆上来——用户指出）；展开体里仍可看完整参数。
  - **委派行的运行态脉冲**（同日定稿，用户指出"子智能体在跑摘要也要脉冲、结束就不要"）：后台委派的结果立即返回（撒种文本 `started subagent <子会话id>`，模型自己也在读的 durable 契约），行 data-state 已成 done——行按结果拆出的 `childSessionId` 对 store 会话表的 `running`，子会话在跑就给行挂 `data-tool-live` 继续脉冲（`session/renderModel.ts` 的 `subagentChildIdOf` 拆串，不匹配不给）、子会话结束自动摘掉；面板「子智能体」行在跑时标签同样自己脉冲（`capsule-live-text` 同一手法）、已结束不脉冲。`prefers-reduced-motion` 同全局脉冲纪律。
- **会话列与面板是两张并列的悬浮卡**（用户 2026-09-25 定稿，覆盖官方"面板是页面的一列"）：两张卡与草稿页的 `.main` 用同一套几何——圆角 `--dsh-radius-panel`、1px 极细描边、卡面 `--card-gradient`、贴身投影 `--shadow-card`、自裁 `overflow:hidden`；四周与两张卡之间各留 8px 缝（缝里透出背景层）。面板宽 320（`box-sizing:border-box`，外沿即 320）。会话页的 `.main` 因此不再自己当卡，只留 `padding:8px`（原来的 `margin:8px` 换成它，卡片外沿逐像素不变）。
- **两种呈现**：push（默认，会话列让位）与 fullscreen（`position:absolute; inset:0` 盖住整张会话卡；底下的会话列 `visibility:hidden` 停绘制）。窄屏（≤760px，手机远程）面板自动整宽。
- **浏览器页**：顶条多一枚返回箭头，正文是工具栏（后退/前进/刷新/地址栏/在系统浏览器打开，iframe 载体另有沙箱开关）+ 占满面板的页面。按钮走 `data-tip` tooltip 与 24px 方钮（与面板控件同规格）。
- **会话设置**：顶条齿轮 → 面板内切视图（返回箭头 + 居中标题），四项：模型 / 权限 / 发送方式 / 插件（内嵌 `PluginsTab`）。**三个选择器都是挂 body 的浮层**（`ModelMenu` / `Dropdown`，portal + fixed 锚在触发器下方）：面板正文是滚动容器，行内或绝对定位的菜单会被裁掉，内联展开还会把下面分区顶下去。权限名称/说明只有 `settings/permissionPreset.ts` 一份本地化表（`presetDropdownOptions`），会话设置、设置页审批分区、新建项目表单共用——引擎 wire 上的 `name` 是裸预设键（`read-only` 等），别直接摆给用户。

## 4. 平台惯例验收清单（每条 = 发布 gate）

1. 无 `cursor:pointer`（手形只给正文里的超链接）；行/菜单项的 hover 只由指针移动触发（§1.10）。
2. 设置页内置主窗口（v3 变更，原"独立窗口"gate 废弃）；弹层 P2 原生可越界。
3. 面板显隐无闪烁/白帧。
4. 右键菜单原生；拖入=附件；⌘C/⌘V 按 macOS 惯例。
5. 对比度达标；VoiceOver 有 label；`prefers-reduced-motion` 全静态。
6. 两端同一 token 源。
7. **黑白检查**：截图仅黑白灰阶（diff 区除外）；**文案检查**：无解释性小字/副标题/注脚。（两条各有已登记例外：插件图标底座 §1.6、插件页副标题 §1.9 第 7 条。）
8. **代表宽度验收集（2026-10-12 Atd 借鉴 #5）**：响应式相关的改动要在代表宽度下过——settings 320 / 480 / 760 / 1000 / 1280，浮层面 320 / 420 / 640，另加短高窗口；每个结构断点**两侧**都要看；**禁止把固定画布截图当响应式证明**。手机远程面（≤760）适用同一张清单。
8. **在亮色外观 + 亮壁纸下过一遍**：透明、圆角与玻璃的缺陷只在亮底上现形，暗壁纸会把它们藏住；§1.4 的亮色投影与 §1.5 的亮色 tint 是各自独立的一套配方，暗色下过不等于亮色下过。
9. **指针静止时不得有新点亮的东西**：hover 是对"指针移动"的响应，不是对"指针位置"的响应——指针不动、而列表滚动或内容重排把另一行送到指针下时，那一行不该被点亮，hover 才现的控件（如侧栏行首的置顶钮，§3.2）也不该冒出来。实现见 §1.10（`:where(html[data-hover-armed])` 门控 + `hoverArming.ts` 的复位时机）。

## 5. 实现衔接

- `frontend/packages/design/tokens.json`（唯一事实源）→ `gen-tokens.mjs` → `tokens.css`（只有这一条生成腿）。
- 组件的落地形态是 `theme.css` / `*.module.css` 的类名配方（§2）；新样式进对应文件的既有配方，不自造第二套，也不写裸 class 内联样式（内联 `style` 还会静默丢掉 `maskImage`，`PITFALLS §1.9`）。
- 原生侧仅系统控件 + NSVisualEffectView。
- **视觉改动双端同轮同步（2026-10-12 Atd 借鉴 #6）**：改了视觉/交互值，同一轮回写本文档与代码两侧（取值记录/规格行随改）——哪一侧改不了，如实报未同步范围，不许宣称两边都完成。
- **组件专属尺寸归主代码（2026-10-12 Atd 借鉴 #7）**：某组件的专属尺寸/间距修在它自己的配方里，**不许每修一处就添一条全局规则**；本文档的规格表是反结算快照，随属主更新。
